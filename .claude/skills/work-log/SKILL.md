# Work Log Skill

> 실습 교육용 작업 변경 로그 기록 워크플로우

## 목적

이 프로젝트에서 진행된 작업을 **교육생이 시작점부터 다시 따라 했을 때 최대한 비슷한 결과물이 나오도록** 재현 가능한 형태로 기록한다.

- **무엇을 했는가** + **왜 그렇게 했는가** + **어떻게 재현하는가** 3가지를 담는다.
- 전체 대화/diff는 git에 있으니 **요약만** 저장한다.

---

## 활성화 조건 (수동 호출 전용)

| 트리거 예시 |
|-------------|
| `/work-log` |
| `/work-log "카드 호버 모션 추가"` (제목 직접 지정) |
| "작업 로그 남겨줘" / "로그 기록해줘" / "이번 작업 정리해줘" |

⚠️ **자동 호출 금지**: 파일 변경/커밋 시 자동 실행하지 않는다. 사용자가 명시적으로 부를 때만 동작.

## 워크플로우

### Step 1. 저장 위치 확인 및 다음 번호 결정

1. `docs/work-log/` 폴더 존재 여부 확인 → 없으면 생성
2. 기존 파일 목록(`ls docs/work-log/`)에서 가장 큰 번호 확인 → `+1`
3. 번호는 3자리 zero-pad (`001`, `002`, ...)

### Step 2. 제목(slug) 결정

- 사용자가 인자로 제목을 줬으면 그대로 사용
- 없으면 직전 작업 맥락에서 한 줄로 추출 → 사용자에게 "이 제목으로 저장할까요?" **1회만** 확인
- slug는 한국어 + kebab-case 혼용 허용. 파일명에 부적합한 문자(`/`, `\`, `:`, `?`, `"`, `<`, `>`, `|`)만 제거

→ 최종 파일명: `docs/work-log/{NNN}-{slug}.md`

### Step 3. 직전 작업 회고 (현재 대화 컨텍스트 기준)

다음 5가지를 현재 세션 대화에서 추출한다. **새로운 탐색/추측 금지** — 이미 일어난 일만 정리.

1. **의도 (User Goal)**: 사용자가 무엇을 요청했는가 (1~2문장)
2. **주요 의사결정**: 진행 중 갈림길에서 내린 선택 (3~5개 bullet, "왜" 포함)
3. **Claude의 핵심 반응**: 재현에 영향 주는 제안/판단만 (예: "신규 생성 대신 기존 X 재활용 권장", "라이브러리 A 대신 B 사용")
4. **변경된 파일**: 추가/수정/삭제 구분, 한 줄 요약
5. **컴포넌트 작업**: 신규/수정/재사용 컴포넌트 목록 (해당 시)

### Step 4. 마크다운 파일 작성

`resources/template.md`의 템플릿을 그대로 사용해 `docs/work-log/{NNN}-{slug}.md` 작성.

빈 섹션은 "해당 없음"으로 채우지 말고 섹션 자체를 생략 (단, 의도/변경된 파일/재현 가이드는 필수).

### Step 5. 인덱스 갱신

`docs/work-log/README.md`가 없으면 생성, 있으면 새 항목을 표 마지막에 추가.

```markdown
# Work Log

실습 교육용 작업 로그 인덱스. 번호 순서대로 따라가면 프로젝트 진화 과정을 재현할 수 있다.

| # | 제목 | 날짜 | 파일 |
|---|------|------|------|
| 001 | 카드 호버 모션 추가 | 2026-04-22 | [001-카드-호버-모션-추가.md](./001-카드-호버-모션-추가.md) |
```

### Step 6. 사용자에게 보고

저장한 파일 경로와 핵심 섹션 3개(의도/변경 파일 수/컴포넌트 작업)만 짧게 보고. 전체 내용 재출력 금지.

## 작성 원칙

### DO
- **재현성 우선**: "이걸 보고 다시 똑같이 만들 수 있는가?"를 기준으로 판단
- **의도와 결정의 근거**를 남긴다 ("왜 이 컴포넌트를 재활용했는지")
- **간결하게**: 한 섹션당 5줄 내외
- **파일 경로는 정확히** (clickable 형태)

### DON'T
- 전체 대화 옮겨 적기
- 코드 diff 그대로 붙이기 (git에 있음)
- 추측이나 미완성 작업 기록 (실제 일어난 일만)
- 빈 섹션을 "해당 없음"으로 채우기
